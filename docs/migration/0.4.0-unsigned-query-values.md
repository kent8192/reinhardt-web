# Unsigned query values in 0.4.0

Native database parameters now include `QueryValue::Uint(u64)`. This preserves
unsigned composite primary keys through query construction and binding.
Unsigned query-builder parameters such as `LIMIT` and `OFFSET` also retain this
representation, including values within the signed integer range.

## Custom executors and exhaustive matches

Add an arm for `QueryValue::Uint(value)` to matches over query parameters and
result values. MySQL executors must bind the original `u64` using the unsigned
driver codec. Executors with signed integer parameters must use
`i64::try_from(value)` and return a `DatabaseErrorKind::Type` error on overflow
before executing the statement. Error messages must omit the parameter value.
Never wrap, clamp, convert through floating point, or substitute a text bind.

For a signed backend, handle the new variant with a checked conversion:

```rust
use reinhardt_db::backends::error::{DatabaseError, DatabaseErrorKind};
use reinhardt_db::backends::types::QueryValue;

fn signed_integer(value: QueryValue) -> Result<i64, DatabaseError> {
    match value {
        QueryValue::Int32(value) => Ok(i64::from(value)),
        QueryValue::Int(value) => Ok(value),
        QueryValue::Uint(value) => i64::try_from(value).map_err(|_| {
            DatabaseError::new(
                DatabaseErrorKind::Type,
                "Unsigned parameter exceeds the backend's signed 64-bit range",
            )
        }),
        _ => Err(DatabaseError::new(
            DatabaseErrorKind::Type,
            "Expected an integer parameter",
        )),
    }
}

assert_eq!(signed_integer(QueryValue::Uint(42)).unwrap(), 42);
assert_eq!(
    signed_integer(QueryValue::Uint(u64::MAX)).unwrap_err().kind(),
    DatabaseErrorKind::Type,
);
```

MySQL result values above `i64::MAX` now use `QueryValue::Uint` instead of
`QueryValue::String`. ORM row conversion preserves these values as JSON numbers,
so models with a `u64` key can deserialize the original value. Smaller MySQL
integer results retain their previous representation.

## Backend behavior

| Backend | Unsigned parameter behavior |
|---------|-----------------------------|
| MySQL | Binds the full `u64` range in pooled and transaction operations |
| PostgreSQL | Checks conversion to `i64`; rejects overflow before execution |
| SQLite | Checks conversion to `i64`; rejects overflow before execution |

These are native database execution APIs (P0). Browser builds using only
`model-info` continue to exclude the database driver graph.

The 0.3.x API retains its signed parameter representation and rejects unsigned
composite keys above `i64::MAX` before execution.
