# reinhardt-web v0.3.17

## Highlights

This release ships a security-motivated correction to GraphQL-over-gRPC request handling. Operation classes are now validated *after* request preparation and document transformation but *before* resolvers execute, closing a gap where a maliciously prepared document could bypass gRPC operation-class enforcement. As part of this fix, `GraphQLGrpcService` now requires custom schemas to be constructed via `GraphQLGrpcService::schema_builder(...)`; constructing the service with an unguarded schema panics, and invalid subscription requests surface their errors through the stream instead of failing silently later. Because this narrowly scoped exception intentionally breaks strict patch compatibility, users should review the [migration guide](instructions/MIGRATION_0.3.17.md) before upgrading.

On the ORM side, `#[field(min_value = ...)]` and `#[field(max_value = ...)]` previously emitted a hard-coded `i64`-suffixed literal in the generated `validate(range(...))` attribute, which caused a compile error whenever the annotated field used a narrower integer type such as `Option<i32>`. The bound is now emitted unsuffixed so it infers its type from the annotated field, matching the behavior of hand-written attributes, with new regression tests pinning the fix.

Release tooling was also hardened: the breaking-change target policy check now runs on the PR head and fails independently of warnings rather than silently succeeding, and the release-preparation workflow now compares `main` against its own stable release tag instead of a newer develop prerelease, preventing misleading API-removal reports. The documentation site's global "Notes" link now correctly points to Reinhardt Press instead of an empty local section.
