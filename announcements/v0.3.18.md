# reinhardt-web v0.3.18

## Highlights

This release delivers a significant fix to exception handling in the HTTP layer. Previously, the `ExceptionHandler` extension point in `reinhardt-http` was public API that could not actually be installed or invoked — the framework had no code path that consulted it. This release installs and threads the handler through the full request lifecycle: `MiddlewareChain` now gains a `with_exception_handler` builder so that errors raised by middleware (CSRF rejection, authorization denial, rate limiting, etc.) are covered in addition to errors from the base handler, and the hook is wired into `ServerRouter`, `UnifiedRouter`, and `HttpServer`, with a single installation point in `src/config/urls.rs` covering server-level middleware as well. Related fixes ensure exception handlers are correctly inherited in nested dispatch, that routing context is preserved and refreshed across all middleware paths, that unmatched routes defer their errors through middleware rather than short-circuiting, and that the legacy exception adapter contract and WASM builder exposure remain intact. Together these changes make custom exception handling reliable and consistent across native and WASM targets, while preserving backward-compatible default behavior when no handler is installed.

The rest of this release focuses on CI/CD and dependency maintenance: constraining AWS Smithy dependencies to a compatible line for stable release builds, fixing release-tag detection ordering in the release workflow, tightening the `deny.toml` policy for `synstructure` versions, and keeping the workspace lockfile out of publish-check archives so packaged crates resolve dependencies correctly from the registry.

## Breaking Changes

No breaking changes in this release.
