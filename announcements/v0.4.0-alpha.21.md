# reinhardt-web v0.4.0-alpha.21

## Highlights

This release centers on testkit ergonomics, several auth/admin correctness fixes, and ongoing CI/dependency-policy maintenance.

**OAuth2 server refresh tokens (breaking).** `reinhardt_auth::oauth2_server` gains opt-in refresh token support for the Authorization Code grant, with mandatory rotation on every use, reuse detection that revokes the entire token family, scope narrowing, resource matching, and in-memory/PostgreSQL storage. This is a breaking change behind new server and client configuration flags — see Breaking Changes below. A related fix tightens refresh-token handling further: the audience allowlist is now enforced and unscoped token families are allowed to refresh correctly.

**Testkit composability improvements.** `test_server_guard` is now a composable rstest fixture, and the new `TestServerClient` keeps its backing HTTP server alive alongside the client it returns, including safe forking (`APIClient::fork()` / `TestServerClient::fork()`) that gives each fork independent default headers, cookies, and transport while sharing DI context and the base URL. A new method-aware async `StubRouter` lets tests register per-method async closures directly, using the framework's own dispatch and 404/405 handling, and deprecates the older `SimpleHandler` adapter. Per-request header and body builders (`APIClient::request(..)`, `TestRequestBuilder`) replace ad hoc header helpers, and `http_client`/`streaming_http_client` fixtures now support configurable total and idle-read timeouts for SSE/long-poll scenarios. `postgres_container` gains a fully configurable variant for custom images, extensions, and server flags, and a new NATS JetStream testcontainers fixture is added (with a follow-up fix making its future `Send`-safe for multithreaded use).

**Admin and auth fixes.** `reinhardt-admin` now correctly infers pgvector field types when `reinhardt-db`'s `pgvector` feature is enabled independently of admin's own flag, and properly rejects vector edits when the admin feature itself is disabled. Two session-backend race conditions are also fixed: `DatabaseSessionBackend::take` deserializes before deleting, and `InMemorySessionBackend` serializes writes against concurrent takes.

**Maintenance.** Several `cargo-deny` policy adjustments keep advisory and dependency-bans scanning green (bit-set/proptest duplication, unsafe-libyaml, rustls 0.21, and zip advisories pulled in transitively by utoipa-swagger-ui), and the runtime SQL audit inventory is refreshed to stay in sync with `SimpleSearchBackend` and admin pgvector forwarding changes.
