# reinhardt-web v0.3.22

## Highlights

This release fixes two feature-gating bugs that affected consumers using granular Cargo features instead of the `standard` or umbrella `middleware` features.

Enabling `middleware-cors` on its own previously failed to compile because the facade module and its re-exports were gated behind the broader `middleware` feature. The facade now follows activation of the optional middleware dependency, so `reinhardt::middleware::cors::create_cors_middleware_from_settings` and `reinhardt::CorsMiddleware` are available whenever the individual component feature is enabled — without pulling in the full `middleware` feature. The same fix covers compression-, security-, rate-limit-, and auth-jwt-only builds, while keeping crate-root re-exports scoped to features that actually provide them, so empty glob imports no longer occur on minimal builds. The native-only WASM boundary is preserved.

Separately, model migrations for byte-vector fields (`Vec<u8>` and `Option<Vec<u8>>`) previously rendered as `BINARY` on PostgreSQL, which PostgreSQL rejects with SQLSTATE `42704`. These fields now render as `BYTEA` on both PostgreSQL and CockroachDB, so generated migrations can be applied without needing an explicit field-type override. PostgreSQL model macro support is also now correctly forwarded through the public `db-postgres` and `db-cockroachdb` facade features, with new regression tests covering dialect rendering, nullability, and real `makemigrations`/`migrate` command execution.
