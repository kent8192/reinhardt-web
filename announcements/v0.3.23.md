# reinhardt-web v0.3.23

## Highlights

This release focuses on fixing method dispatch and feature-forwarding bugs that affected facade consumers, test tooling, and routing.

Routers built with `handler_arc`, `handler`, `view`, and `view_named` previously rejected `HEAD` and `OPTIONS` requests with `405 Method Not Allowed` even though these routes are meant to be method-agnostic. The route compiler now registers these routes across every HTTP method table, including an open-ended fallback table for extension methods, while keeping explicitly declared endpoints scoped to their own method. `HEAD` requests now correctly traverse the full router hierarchy, preserve response headers, and return an empty body, matching the behavior users expect from mounted shared routers.

The `reinhardt-testkit` `APIClient` no longer appends a second value when a per-request header overrides a default header of the same name (e.g., `Authorization`). Overrides now replace the default for that request only, while unrelated defaults and subsequent requests retain their original values — preventing authorization tests from silently running with the wrong credentials. A related fix also ensures repeated per-request header values are correctly retained rather than dropped.

Facade consumers that depend only on `reinhardt-web` with `websockets` or `graphql` combined with `test` (without enabling `full`) can now import `websocket_server`, `websocket_client`, and `graphql_server` test fixtures, since the corresponding optional test features are now weakly forwarded to `reinhardt-test`.

Additionally, the `postgres_container` testkit fixture's documentation is corrected to describe PostgreSQL 16, matching the actual `postgres:16-alpine` image used — no behavioral change, just accurate docs.

## Breaking Changes

No breaking changes in this release.
