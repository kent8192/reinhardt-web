# reinhardt-web v0.3.16

## Highlights

This release focuses heavily on forms rendering and hydration correctness. Dynamic `RadioSelect` fields now expose proper accessible group semantics: default radio groups render with `fieldset`/`legend`, while custom wrappers get a named group instead of a dangling label that pointed at a nonexistent target. Individual options retain their own labels, and behavior has been verified against live Chrome across desktop and narrow viewports.

Generated `form!` fields also gain full support for validation and display attributes that were previously silently dropped — disabled and read-only fields are now correctly non-editable, native HTML5 validation attributes (pattern, min/max length, numeric bounds) are emitted, and help text renders as accessible, properly escaped content across ordinary, grouped, radio-choice, and collection controls.

A broader set of fixes addresses form value synchronization between Rust state and the DOM. Controls now reliably reflect their declared initial values instead of falling back to browser defaults, and mounted bindings survive signal updates and runtime resets without the control being replaced. This includes preserving textarea and select state during hydration, retaining custom widget subscriptions after a native reset, evaluating static select choices only once, and correctly normalizing newline handling in textareas. Core's reactive layer was also tightened to defer and deduplicate layout effects within batches, flushing them before passive effects run, which reduces redundant work and improves consistency during form resets.

Additionally, CI reliability improvements restore the dependency audit (removing unused syntect loaders that caused duplicate dependency versions) and isolate test fixtures so admin script and audit-backend tests no longer leak process state or share in-memory databases between runs.
