# reinhardt-web v0.3.13

## Highlights

This release ships an important security fix in `reinhardt-utils`: the Azure blob storage backend previously constructed request URLs from caller-controlled blob names without rejecting `.` and `..` path segments. This allowed crafted names to escape a configured prefix or container via `../` traversal after URL normalization, potentially letting authenticated callers read, overwrite, probe, or delete blobs outside the intended scope. The fix validates blob names in `get_full_blob_name`, rejecting ambiguous dot-segment components before URL construction while still allowing normal nested paths like `images/logo.png`. The `save`, `open`, and `delete` operations now propagate an `io::Result`, returning an `InvalidInput` error for invalid names, and `exists` safely returns `false` for such inputs. Documentation in the static files cookbook has been updated to reflect this behavior.

This release also stabilizes the formatter's handling of direct implicit-capture `page!({ ... })` bodies. Previously, page captures whose first DSL child was an interpolation would accumulate extra indentation on every `fmt-all` pass, since the formatter never reached a stable fixed point. By routing these bodies through the existing closure indentation normalization path, the formatter now converges correctly without altering the emitted page syntax, backed by a new two-pass formatter regression test.

Additionally, a redundant rustdoc link target in the `db` crate has been cleaned up.
