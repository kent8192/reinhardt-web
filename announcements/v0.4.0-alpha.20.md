# reinhardt-web v0.4.0-alpha.20

## Highlights

This release focuses heavily on database and migration correctness, along with new typed PostgreSQL capabilities.

On the migrations and CLI side, the capability-aware CLI now correctly scopes `makemigrations` to only the installed app instead of proposing migrations for linked models as well, and global verbosity counting, conditional dependency resolution, manual migration proposal checks, and target validation during history reconciliation are all corrected. Database URLs no longer leak credentials in command logs. Filesystem-backed migrations gain the ability to load SQL from `include_str!` assets, with fixes to ensure repository reads (history and duplicate detection) resolve those assets correctly, and `database_only` operations are now properly excluded from file-based model-state replay so they no longer corrupt field types or inject spurious schema differences.

On the ORM/database layer, MySQL bulk inserts now correctly avoid `RETURNING`, apply field metadata, and preserve datetime/JSON bindings and row semantics. `Session` gains several correctness fixes: `list_all` now properly quotes identifiers containing special characters, lookups honor custom primary-key codecs instead of naive string conversion, and unsigned argument binding is covered by real encoder-level tests. Several breaking but intentional changes land to improve correctness: unsigned composite-key values are preserved end-to-end via a new `QueryValue::Uint`, NULL elements within PostgreSQL arrays are now preserved rather than rejected, native PostgreSQL NULL parameters no longer default to an implicit INT4 type (requiring explicit casts in some SQL), and PostgreSQL extensions created via migrations now have a safe, typed reversal path.

New checked query capabilities add typed SQLite foreign-key toggling and `PRAGMA database_list` inspection, replacing raw SQL string construction. Migration support expands with structured PostgreSQL sequence and identity (ALWAYS/BY DEFAULT) operations. A new `reinhardt-query-sqlx` adapter crate lays the foundation for SQLx-based execution, including a self-contained pgvector-compatible binary codec that avoids transitive SQLx version conflicts. Additional fixes address standalone `reinhardt-conf` database settings compilation, backend-free `reinhardt-storages` builds, and strict auth validation on the `develop/0.4.0` line.
