# reinhardt-web v0.4.0-alpha.22

## Highlights

This release adds a significant ORM improvement and ships several dependency and security maintenance fixes.

The `#[model]`/`#[rel]` macros now support `shared_fields` on `#[rel(foreign_key, ...)]` relations (#6827), letting a foreign key declare columns that both models carry under the same name — for example a tenant-scoped key like `(tenant, task_id) REFERENCES tasks (tenant, id)`. This closes a gap where multi-tenant, row-level-security setups had to drop such keys into database-only migrations instead of expressing them in model state. Alongside this, the previously-parsed-but-ignored `db_constraint = "..."` attribute now actually names the constraint in migration state and `constraint_fields()` lookups, and the generated `{field}_id` companion field for a relation now inherits the relation field's visibility (a `pub` relation produces a `pub` id field).

On the dependency front, this release restores a healthy `cargo deny` audit on `develop/0.4.0`. PR #6829 bridges a transient duplicate `aws-smithy-schema` version conflict introduced by an upstream `aws-smithy-runtime` release, and PR #6841 goes further by removing the legacy `rustls`-based AWS SDK transports entirely (remediating RUSTSEC-2026-0382), switching the AWS Secrets Manager provider to the SDK's current HTTP/HTTPS transport, and adding bounded, time-tracked allowances for a handful of incompatible RustCrypto release lines. PR #6832 forward-merges the stable `main` branch's 0.3.24/0.3.25 fixes (covering session/auth middleware behavior, OAuth token handling, SQLite task fields, and various advisory fixes) into the `0.4.0` development line to keep the branches in sync.
