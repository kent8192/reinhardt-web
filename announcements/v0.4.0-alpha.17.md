# reinhardt-web v0.4.0-alpha.17

## Highlights

This release introduces a full OAuth 2.0 authorization server for `reinhardt-auth`, replacing the previous in-process helpers with routable authorization, token, revocation, introspection, and metadata endpoints. It supports Authorization Code with mandatory PKCE (S256) and Client Credentials grants, backed by an atomic PostgreSQL store suitable for production use. The new server closes several gaps in the legacy implementation: it now rejects expired and replayed tokens, stops issuing unusable refresh tokens, validates registered clients and exact redirect URIs before issuing codes, and makes authorization lifecycle transitions atomic to eliminate concurrency bugs. Additional fixes correct HTTP error responses, reject case-variant resource audiences, and move RSA signing operations to blocking workers to avoid stalling the async runtime.

Building on this, the release also adds an opt-in OpenID Connect (OIDC) layer on top of the OAuth server: OIDC grants are isolated from core OAuth flows, subjects and signing-key state are now persisted, and the code flow along with provider metadata discovery is served over HTTP. OIDC continuations are bound to sessions, token lifetimes are validated to reject subsecond configurations, and expired-code replay now revokes associated tokens, hardening the flow against misuse.

Separately, generated Pages and RESTful management binaries now select the invoked command before loading project settings. This means `collectstatic` and `buildstatic` only validate the configuration they actually need, so missing JWT, session, or database secrets no longer block static asset publication. `runserver` and legacy custom commands continue to require full, strict settings validation as before.

A temporary, narrowly scoped `cargo-deny` exception was also added to unblock the dependency policy check affected by a Salsa advisory in an optional developer shell dependency; this does not affect production builds and is tracked for removal once a compatible upgrade lands.
