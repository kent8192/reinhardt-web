# reinhardt-web v0.3.19

## Highlights

This release fixes a bug in the browser `use_websocket` hook where existing reconnection options were silently ignored. Previously, the hook's connection closure was invoked only once, so a peer disconnect would simply update the signal and call `on_close` without ever attempting to reconnect. Now, `auto_reconnect`, `max_reconnect_attempts`, and `reconnect_delay` are properly honored, with the retry budget resetting after a successful reconnection.

Alongside this, the shared connection handle gains RAII ownership over its socket, event closures, and a cancellable retry timer, while browser callbacks and timers hold only weak references to avoid leaks. Calling `close()` is now explicit, terminal, and idempotent, pending retries are cancelled when the last handle is dropped, and handles remain usable after a reconnect. This lays the groundwork for a framework-owned WebSocket connection lifecycle rather than requiring application-specific retry logic. No public API signatures or new dependencies are introduced; applications that prefer the old behavior can set `auto_reconnect: false`. Native/SSR usage remains unaffected (a no-op).

This release also updates internal agent/contributor documentation to require destination-specific policy verification before external publications (Issues, PRs, comments, reviews), replacing a prior workflow that mandated upstream Issue creation. This is a documentation-only change with no effect on the framework's runtime behavior or public API.

## Breaking Changes

No breaking changes in this release.
