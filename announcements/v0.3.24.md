# reinhardt-web v0.3.24

## Highlights

This release ships a significant security remediation (PR #6739) addressing 24 findings from a repository security scan. It validates SQL structure inputs, upload paths and sizes, and protobuf parsing; resolves current session accounts and privileges before authentication/CSRF decisions; binds and validates OAuth/OIDC destinations; validates redirect hosts/targets; enforces admin tenant ownership with typed predicates; neutralizes formula injection in CSV/TSV exports; and bounds plugin WASM memory, tables, and lifecycle deadlines. This change is **breaking** and includes a migration guide — see the Breaking Changes section below.

Database migrations are more correct: forward `AlterColumn` SQL on PostgreSQL/CockroachDB now properly emits `SET NOT NULL` / `DROP NOT NULL` so nullability-only migrations actually apply the constraint change, and the NOT NULL constraint is preserved when a primary key column is demoted, avoiding an invalid "column is in a primary key" failure.

Authentication and sessions see several reliability fixes: NAT64 addresses that embed a public IPv4 are now accepted correctly in both `reinhardt-auth` and `reinhardt-dentdelion`, OAuth callback state is consumed before rejecting an empty binding (preventing state reuse), and CSRF middleware now issues tokens for the rotated session ID after session rotation.

The task queue backend is hardened: the SQLite result backend preserves the originally persisted `created_at` timestamp on read instead of overwriting it, and unknown/corrupted status values now surface as explicit backend errors rather than silently defaulting to "pending." The admin module also propagates database errors from scoped detail fetches instead of swallowing them, and `reinhardt-dentdelion`'s owner-scoped event bus calls have been ported to shared bus state. Several CI/dependency-policy adjustments keep the dependency audit and release pipeline green.
