# reinhardt-web v0.3.20

## Highlights

This release focuses on a security-relevant authentication fix along with routine CI and dependency maintenance. OIDC ID token validation now correctly accepts array-valued `aud` (audience) claims, not just strings. Previously, ID tokens with a multi-value audience array would fail deserialization even when they contained a valid, configured client ID. The public `IdToken::aud` field remains a `String` for backward compatibility, but validated tokens now correctly return the matched client ID from anywhere in the audience array, and the `azp` (authorized party) claim is validated on multi-audience tokens to prevent audience-confusion issues.

On the maintenance side, the CI dependency policy (`cargo-deny`) is updated to allow compatible `rand` 0.10.x patch releases instead of pinning an exact version exception, preventing spurious Security Audit failures as the dependency graph shifts. Unused `cargo-deny` policy entries (duplicate-version skips and an OpenSSL license allowance no longer needed) are also cleaned up, and the internal issue-triage policy documentation is simplified by removing the `agent-suspect` label workflow in favor of counting all open critical/high issues in RC stability monitoring.
