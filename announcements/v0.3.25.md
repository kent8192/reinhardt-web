# reinhardt-web v0.3.25

## Highlights

This release is a maintenance release that fixes several regressions surfaced by CI and real-world usage since v0.3.24.

The most user-facing fix addresses `SimpleSearchBackend`: when combined with the PostgreSQL dialect, it previously produced `LIKE` patterns with an `ESCAPE '\'` clause that broke chained filters (such as `SimpleOrderingBackend`, `SynonymExpander`, and `RelevanceScorer`), causing them to fail with an `InvalidQuery` error. PostgreSQL output no longer includes the problematic `ESCAPE` clause, and LIKE wildcards are now escaped exactly once instead of twice, fixing cases where searches like `a_b` incorrectly matched only the literal text `a\_b`. As a related, intentional behavior change, search text containing a backslash is now rejected with `FilterError::InvalidParameter`, for consistency with other filters and to avoid backend-dependent matching ambiguity.

On the tooling side, `runserver`'s autoreload on Linux no longer deadlocks when watching source trees with a few hundred directories — a bounded internal channel could fill up during initial watch registration and stall the `notify` event-loop thread, silently breaking file-change detection. The watcher now filters irrelevant events up front and forwards them through an unbounded channel, preventing the stall.

Additionally, `QuerySet` regains its `UnwindSafe`/`RefUnwindSafe` auto-trait implementations, which had been inadvertently lost when join conditions moved to a more structured internal representation — this keeps the crate's public API compatible with v0.3.24 rather than requiring a 0.4.0 bump. A CI dependency-advisory false positive for `zip` (pulled in transitively via `utoipa-swagger-ui`'s build script, and not exploitable in this context) is also suppressed, and test expectations for CASE-expression SQL on MySQL and SQLite were corrected to match renderer output.

## Breaking Changes

No breaking changes in this release.
