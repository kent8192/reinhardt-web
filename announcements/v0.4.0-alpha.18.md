# reinhardt-web v0.4.0-alpha.18

## Highlights

This release focuses on correctness and stability fixes across HTTP, ORM, and migrations, along with dependency cleanup ahead of stable 0.4.0.

HTTP macro endpoints can now return `ViewResult<StreamingResponse<StreamBody>>` directly, and manual handlers can stream responses via `.into()` or `Response::with_stream`. Frames are sent on demand over HTTP/1, HTTP/2, and standalone `runserver`, with proper error propagation and producer cleanup on client disconnect — unblocking use cases like Server-Sent Events that previously failed to compile or buffer correctly.

A significant **breaking fix** corrects `#[model]` codegen: nullable foreign-key and one-to-one relations now always generate `Option<PrimaryKey>` fields, regardless of whether model forms are enabled, so the generated Rust type matches actual database nullability. Existing code assigning bare IDs to these fields will need to switch to `Some(id)`/`None`.

Migration authoring is more robust: long builder chains (256+ operations) no longer risk a stack overflow due to a new iterative resolution walk, and `makemigrations` now correctly honors the configured migration directory (including rejecting invalid non-UTF-8 paths).

Security-wise, OIDC ID token handling now validates `azp` on multi-audience tokens and accepts array-valued audiences. WebSocket reconnect logic now correctly honors retry options with owned cancellation. The temporary `aws-smithy-types` version pin has been removed now that upstream `aws-smithy-json` resolves cleanly against current releases. A large forward-merge from `main` also brings in fixes for SQL literal generation, JSON/BTreeMap OpenAPI schemas, string primary keys, bounded foreign-key names, PostgreSQL migration locks, and typed catch-all routes.

## Breaking Changes

No breaking changes in this release.
